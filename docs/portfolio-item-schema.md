# รูปแบบ JSON สำหรับแลกเปลี่ยนข้อมูล Portfolio Item

## 1. จุดประสงค์

เอกสารนี้จัดทำขึ้นเพื่อกำหนดรูปแบบไฟล์ JSON ที่ใช้สำหรับแลกเปลี่ยนข้อมูล Portfolio Item ระหว่างกลุ่ม โดยทุกกลุ่มจะต้องใช้โครงสร้างข้อมูลเดียวกัน เพื่อให้สามารถนำไฟล์ของกลุ่มอื่นเข้ามาใช้งานในระบบได้โดยไม่มีปัญหา

รูปแบบนี้จะใช้โครงสร้าง Portfolio Item เดิมจาก Checkpoint และเพิ่มข้อมูลที่จำเป็นสำหรับการแลกเปลี่ยน เช่น รหัสการแลกเปลี่ยน กลุ่มต้นทาง และข้อมูล Challenge

## 2. โครงสร้างไฟล์ JSON

ไฟล์ JSON ที่ใช้แลกเปลี่ยนข้อมูลจะประกอบด้วยข้อมูลหลัก 3 ส่วน ได้แก่

- ข้อมูลเกี่ยวกับรูปแบบไฟล์และเวอร์ชัน
- ข้อมูลแหล่งที่มาของ Portfolio Item
- ข้อมูล Portfolio Item ที่ต้องการแลกเปลี่ยน

ตัวอย่างโครงสร้างไฟล์:

```json
{
  "schema": "powerup-portfolio-item",
  "version": 1,
  "exchangeId": "exchange-001",
  "issuedAt": "2026-11-18T10:00:00.000Z",
  "source": {
    "group": "Group A",
    "booth": "Challenge Booth",
    "challenge": "Challenge 1",
    "host": "Host Name"
  },
  "item": {}
}
```

## 3. รายละเอียดข้อมูลในไฟล์

| ชื่อ Field | ชนิดข้อมูล | รายละเอียด |
|---|---|---|
| schema | String | ชื่อรูปแบบไฟล์ ต้องเป็น powerup-portfolio-item |
| version | Number | เวอร์ชันของรูปแบบไฟล์ ปัจจุบันใช้ 1 |
| exchangeId | String | รหัสสำหรับระบุการแลกเปลี่ยนแต่ละครั้ง |
| issuedAt | String | วันและเวลาที่สร้างไฟล์ |
| source | Object | ข้อมูลของกลุ่มที่เป็นผู้ส่ง |
| item | Object | ข้อมูล Portfolio Item ที่ต้องการส่ง |

## 4. รายละเอียดข้อมูล Source

ข้อมูล Source ใช้ระบุว่า Portfolio Item นี้มาจากกลุ่มหรือกิจกรรมใด

| ชื่อ Field | ชนิดข้อมูล | รายละเอียด |
|---|---|---|
| group | String | ชื่อกลุ่มต้นทาง |
| booth | String | ชื่อบูธหรือกิจกรรม |
| challenge | String | ชื่อ Challenge ที่เข้าร่วม |
| host | String | ชื่อผู้ดูแลกิจกรรม |

## 5. โครงสร้าง Portfolio Item

ข้อมูลภายใน item จะใช้โครงสร้างเดียวกับ Portfolio Item ที่มีอยู่ในระบบเดิม เพื่อให้สามารถนำไปใช้งานต่อได้โดยไม่ต้องเปลี่ยนรูปแบบข้อมูล

| ชื่อ Field | ชนิดข้อมูล | รายละเอียด |
|---|---|---|
| id | String | รหัสประจำ Item |
| title | String | ชื่อผลงานหรือกิจกรรม |
| type | String | ประเภทของผลงาน |
| date | String | วันที่ทำกิจกรรม รูปแบบ YYYY-MM-DD |
| role | String | หน้าที่หรือบทบาทที่ได้รับ |
| description | String | รายละเอียดของผลงาน |
| skills | Array | รายการทักษะที่ได้ใช้ |
| reflection | Object | ข้อมูลสะท้อนการเรียนรู้ |
| evidence | Array | รายการลิงก์หลักฐาน |

### ข้อมูล Reflection

Reflection ใช้บันทึกสิ่งที่ผู้เข้าร่วมได้ทำและเรียนรู้จากกิจกรรม โดยมี 4 Field ดังนี้

| ชื่อ Field | ชนิดข้อมูล | รายละเอียด |
|---|---|---|
| whatIDid | String | สิ่งที่ได้ลงมือทำ |
| whatILearned | String | สิ่งที่ได้เรียนรู้ |
| challenge | String | ปัญหาหรือความท้าทายที่พบ |
| nextStep | String | สิ่งที่ต้องการพัฒนาต่อ |

## 6. เงื่อนไขการตรวจสอบข้อมูล

ก่อนนำไฟล์ JSON เข้าสู่ระบบ จะต้องตรวจสอบข้อมูลตามเงื่อนไขต่อไปนี้

1. ไฟล์ต้องเป็น JSON ที่มีรูปแบบถูกต้อง
2. ต้องมี Field ที่จำเป็นครบถ้วน
3. ข้อมูลแต่ละ Field ต้องมีชนิดตรงตามที่กำหนด
4. Field ที่เป็นข้อความต้องไม่เป็นค่าว่าง
5. version ต้องเป็น 1
6. exchangeId ต้องมีค่าและไม่ซ้ำกับรายการที่เคยนำเข้า
7. issuedAt ต้องเป็นวันและเวลาที่ถูกต้อง
8. date ต้องเป็นวันที่จริงในรูปแบบ YYYY-MM-DD
9. skills และ evidence ต้องเป็น Array
10. ลิงก์ใน evidence ต้องเป็น URL ที่ขึ้นต้นด้วย HTTP หรือ HTTPS

หากข้อมูลไม่ผ่านเงื่อนไข ระบบจะแจ้งข้อผิดพลาดและไม่อนุญาตให้นำเข้าข้อมูลดังกล่าว

## 7. การใช้งานร่วมกับระบบเดิม

เพื่อให้ระบบใหม่สามารถทำงานร่วมกับระบบเดิมได้ ข้อมูลภายใน item จะต้องมีโครงสร้างตรงกับ Portfolio Item ที่ใช้ในโปรเจกต์ปัจจุบัน

การเพิ่ม JSON Wrapper จะเป็นการเพิ่มข้อมูลสำหรับการแลกเปลี่ยนเท่านั้น โดยไม่เปลี่ยนแปลงโครงสร้าง Portfolio Item เดิม
