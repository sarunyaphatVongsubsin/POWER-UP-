# รูปแบบ JSON สำหรับแลกเปลี่ยนข้อมูล Portfolio Item

## 1. จุดประสงค์

เอกสารนี้จัดทำขึ้นเพื่อกำหนดรูปแบบไฟล์ JSON สำหรับใช้แลกเปลี่ยนข้อมูล Portfolio Item ระหว่างกลุ่ม โดยทุกกลุ่มจะใช้โครงสร้างข้อมูลเดียวกัน เพื่อให้สามารถนำข้อมูลจากกลุ่มอื่นเข้าสู่ระบบได้อย่างถูกต้องและลดปัญหาความไม่ตรงกันของข้อมูล

รูปแบบ JSON นี้ใช้โครงสร้าง Portfolio Item เดิมจาก Checkpoint และเพิ่มข้อมูลที่จำเป็นสำหรับการแลกเปลี่ยน ได้แก่ รหัสการแลกเปลี่ยน ข้อมูลกลุ่มต้นทาง และข้อมูลกิจกรรมที่เข้าร่วม โดยไม่เปลี่ยนแปลงโครงสร้าง Portfolio Item เดิม

## 2. โครงสร้างไฟล์ JSON

ไฟล์ JSON สำหรับแลกเปลี่ยนข้อมูลประกอบด้วยข้อมูลหลัก 3 ส่วน ได้แก่

- ข้อมูลรูปแบบไฟล์และเวอร์ชัน
- ข้อมูลแหล่งที่มาของ Portfolio Item
- ข้อมูล Portfolio Item ที่ต้องการแลกเปลี่ยน

ตัวอย่างโครงสร้างไฟล์:

```json
{
  "schema": "powerup-portfolio-item",
  "version": 1,
  "exchangeId": "exchange-001",
  "issuedAt": "2026-11-18T10:00:00.000Z",
  "source": {
    "group": "Group A",
    "booth": "Challenge Booth",
    "challenge": "Challenge 1",
    "host": "Host Name"
  },
  "item": {}
}
```

## 3. รายละเอียดข้อมูลในไฟล์

| ชื่อ Field | ชนิดข้อมูล | รายละเอียด |
|---|---|---|
| schema | String | ชื่อรูปแบบไฟล์ ต้องเป็น `powerup-portfolio-item` |
| version | Number | เวอร์ชันของรูปแบบไฟล์ ปัจจุบันกำหนดเป็น `1` |
| exchangeId | String | รหัสสำหรับระบุการแลกเปลี่ยนแต่ละครั้ง ต้องไม่ซ้ำกับรายการที่เคยนำเข้า |
| issuedAt | String | วันและเวลาที่สร้างไฟล์ ในรูปแบบ ISO 8601 |
| source | Object | ข้อมูลของกลุ่มหรือกิจกรรมที่เป็นแหล่งที่มาของ Item |
| item | Object | ข้อมูล Portfolio Item ที่ต้องการส่ง |

## 4. รายละเอียดข้อมูล Source

ข้อมูล Source ใช้ระบุแหล่งที่มาของ Portfolio Item เพื่อให้ทราบว่าข้อมูลดังกล่าวมาจากกลุ่มหรือกิจกรรมใด

| ชื่อ Field | ชนิดข้อมูล | รายละเอียด |
|---|---|---|
| group | String | ชื่อกลุ่มต้นทาง |
| booth | String | ชื่อบูธหรือกิจกรรม |
| challenge | String | ชื่อ Challenge ที่เข้าร่วม |
| host | String | ชื่อผู้ดูแลกิจกรรม |

ทุก Field ภายใน Source ต้องมีข้อมูลเป็น String และต้องไม่เป็นค่าว่าง

## 5. โครงสร้าง Portfolio Item

ข้อมูลภายใน `item` ใช้โครงสร้างเดียวกับ Portfolio Item ที่มีอยู่ในระบบเดิม เพื่อให้สามารถนำข้อมูลที่ได้รับไปใช้งานต่อได้โดยไม่ต้องเปลี่ยนรูปแบบข้อมูล

| ชื่อ Field | ชนิดข้อมูล | รายละเอียด |
|---|---|---|
| id | String | รหัสประจำ Item |
| title | String | ชื่อผลงานหรือกิจกรรม |
| type | String | ประเภทของผลงาน |
| date | String | วันที่ทำกิจกรรม ในรูปแบบ `YYYY-MM-DD` |
| role | String | หน้าที่หรือบทบาทที่ได้รับ |
| description | String | รายละเอียดของผลงาน |
| skills | Array | รายการทักษะที่ได้ใช้ โดยสมาชิกแต่ละรายการเป็น String |
| reflection | Object | ข้อมูลสะท้อนการเรียนรู้ |
| evidence | Array | รายการ URL ของหลักฐาน โดยแต่ละรายการต้องเป็น HTTP หรือ HTTPS URL |

### 5.1 ข้อมูล Reflection

Reflection ใช้บันทึกสิ่งที่ผู้เข้าร่วมได้ลงมือทำ สิ่งที่ได้เรียนรู้ ปัญหาที่พบ และแนวทางการพัฒนาต่อ โดยประกอบด้วย 4 Field ดังนี้

| ชื่อ Field | ชนิดข้อมูล | รายละเอียด |
|---|---|---|
| whatIDid | String | สิ่งที่ได้ลงมือทำ |
| whatILearned | String | สิ่งที่ได้เรียนรู้ |
| challenge | String | ปัญหาหรือความท้าทายที่พบ |
| nextStep | String | สิ่งที่ต้องการพัฒนาต่อ |

ทุก Field ภายใน Reflection ต้องเป็น String และต้องไม่เป็นค่าว่าง

## 6. เงื่อนไขการตรวจสอบข้อมูล

ก่อนนำไฟล์ JSON เข้าสู่ระบบ จะต้องผ่านการตรวจสอบตามเงื่อนไขต่อไปนี้

1. ไฟล์ต้องเป็น JSON ที่มีรูปแบบถูกต้อง
2. ต้องมี Field ที่จำเป็นครบถ้วนตามโครงสร้างที่กำหนด
3. ชนิดข้อมูลของแต่ละ Field ต้องตรงตามที่กำหนด
4. Field ที่เป็นข้อความต้องไม่เป็นค่าว่าง
5. ค่า `schema` ต้องเป็น `powerup-portfolio-item`
6. ค่า `version` ต้องเป็น `1`
7. ค่า `exchangeId` ต้องมีข้อมูลและไม่ซ้ำกับ exchangeId ที่เคยนำเข้าในระบบ
8. ค่า `issuedAt` ต้องเป็นวันและเวลาที่ถูกต้องในรูปแบบ ISO 8601
9. ค่า `date` ภายใน Portfolio Item ต้องเป็นวันที่จริงในรูปแบบ `YYYY-MM-DD`
10. ค่า `skills` และ `evidence` ต้องเป็น Array
11. URL ภายใน `evidence` ต้องเป็น URL ที่ถูกต้องและใช้ HTTP หรือ HTTPS

หากข้อมูลไม่ผ่านเงื่อนไขข้อใดข้อหนึ่ง ระบบจะแสดงข้อความแจ้งข้อผิดพลาดและไม่อนุญาตให้นำเข้าข้อมูลดังกล่าว

## 7. การใช้งานร่วมกับระบบเดิม

เพื่อให้ระบบแลกเปลี่ยนข้อมูลสามารถทำงานร่วมกับระบบเดิมได้ ข้อมูลภายใน `item` จะต้องมีโครงสร้างตรงกับ Portfolio Item ที่ใช้อยู่ในโปรเจกต์ปัจจุบัน

การเพิ่ม JSON Wrapper เป็นเพียงการเพิ่มข้อมูลสำหรับการแลกเปลี่ยน เช่น `exchangeId`, `issuedAt` และ `source` โดยไม่เปลี่ยนแปลงโครงสร้างข้อมูล Portfolio Item เดิม

เมื่อผู้ใช้ต้องการนำเข้าไฟล์ ระบบจะตรวจสอบข้อมูล JSON และตรวจสอบรหัส `exchangeId` ที่ซ้ำกับรายการเดิมก่อนดำเนินการ Import เพื่อป้องกันการนำเข้าข้อมูลซ้ำ
